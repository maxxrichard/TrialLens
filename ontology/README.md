# TrialLens ontology

The ontology is defined as code in this folder and reviewed like any other change.

| File | Content |
|---|---|
| `object_types/*.yaml` | 35 object types in 8 domains, with properties, primary keys, markings and backing |
| `link_types.yaml` | 42 one-to-many link types (foreign key on the *many* side) |
| `action_types.yaml` | 7 action types: the only write path, all audited in the action log |

## Conventions

* **Property names** in YAML are the backing dataset columns (`snake_case`). The Foundry
  property API name is the `camelCase` form (`latest_ptau217` → `latestPtau217`), which is
  what Functions, Workshop and OSDK clients use.
* **Primary keys** are stable, source-derived identifiers. Patients are keyed by the
  pseudonym `TL-P-<16 hex>`; MRNs never reach the ontology.
* **Markings** on an object type must cover the markings of its backing dataset. Objects
  joining personal data from several domains carry all relevant markings (for example
  `OmicsSample` = pseudonymised clinical + genetic).
* **Backing** is one of:
  * `source` — projection of a clean or curated dataset, optionally with `filter`,
    `group_by`/`aggregations` (Spark SQL) and `columns` (property → expression);
  * `builder` — named Python builder in `triallens/ontology_backing.py`;
  * `writeback: true` — objects created only through actions (cohorts, reviews).

Backing datasets are generated by `triallens/foundry/ontology_transforms.py` (one
transform per object type) and checked end-to-end in CI against these definitions:
column names, types, primary-key uniqueness and referential integrity of every link.

|---|---|
